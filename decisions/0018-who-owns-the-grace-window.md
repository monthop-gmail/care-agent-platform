# ADR-0018: ใครเป็นเจ้าของ `grace_minutes` — ปิดสองปลายที่ไม่มีความหมาย ปล่อยตรงกลางให้ทีมดูแล

**Status:** Accepted (2026-09-28)
**ตอบ:** `task-6bb0d2bd` Phase A ข้อ 2 · ต่อจาก [ADR-0016](0016-a-deadline-is-a-care-decision.md) ข้อที่ยังไม่ตัดสินข้อ 2

## Context

ADR-0016 ทำให้ `CareRoutineItem.grace_minutes` กลายเป็นตัวกำหนดว่าคำเตือนอยู่บนจอนานแค่ไหน
ก่อนหน้านั้นค่านี้ถูกเก็บไว้เฉย ๆ **ไม่มีโค้ดไหนอ่านเลย**

> การตั้งค่าที่เคยไม่มีผล วันนี้มีผลกับสิ่งที่ผู้ป่วยเห็น — และไม่มีใครที่เคยตั้งมันรู้เรื่องนี้

## Decision

### 1. อำนาจที่มีอยู่แล้วคือคำตอบ ไม่ต้องสร้างชั้นใหม่

แก้ได้ต้องผ่านสองด่านที่มีอยู่แล้ว: permission `care.routine.manage` (API) และ consent
`care.manage` ต่อผู้ป่วยรายนั้น (`get_patient(..., required_scope="care.manage")`)

**ไม่เพิ่ม role ใหม่** — การเพิ่มบทบาทเพื่อคุมฟิลด์เดียว ทำให้ระบบสิทธิ์มีสองที่ที่ต้องดู
และที่ที่สองมักเป็นที่ที่คนลืม

### 2. ปิดสองปลายที่ไม่มีความหมาย และ **ไม่ปิดตรงกลาง**

| ขอบ | ค่า | เหตุผล |
|---|---|---|
| floor | 5 นาที | ต่ำกว่านี้คำเตือนหมดอายุก่อนที่คนจะทันขยับ = **ไม่เคยเตือน** |
| ceiling | 1440 นาที | เกินหนึ่งวัน กิจวัตร "รายวัน" จะทับรอบของวันถัดไปเอง |
| เส้นเตือน | 240 นาที | กว้างได้ แต่ **ต้องไม่ผ่านเงียบ ๆ** |

> ช่วงสองถึงหกชั่วโมงเป็นการตัดสินของทีมดูแล ไม่ใช่ของเรา · ผู้ป่วยที่กินวิตามินวันละครั้ง
> กับผู้ป่วยที่กินยาความดันสี่เวลา ไม่ควรถูกบังคับด้วยเลขเดียวกันจากคนที่ไม่ได้อยู่ในบ้านนั้น

### 3. ค่าที่กว้างผิดปกติต้องเห็นได้สามที่

* `check_grace()` คืนข้อความเตือนที่บอก **ผลจริง** ("จะค้างบนจอได้ถึง N ชั่วโมงหลังถึงกำหนด")
* API ตอบกลับพร้อม `grace_minutes` และ `grace_warning` เสมอ — คนตั้งค่าไม่ต้องเดาว่ามีผลอะไร
* audit เก็บ `grace_flag` เป็น `normal`/`wide` (เป็น `CODE` ตาม ADR-0011 จึงไม่พา PII เข้า)

### 4. ยังไม่ทำ tenant override

ยังไม่มี tenant ที่สอง · ชั้น config ที่ยังไม่มีใครใช้จะกลายเป็นที่ที่ค่าผิดไปซ่อนอยู่
เมื่อมี use case จริง รูปของ floor/ceiling ควรตามรูปของ `floor.capabilities` ใน
`policies/care-authority-map.yaml` ที่ใช้อยู่แล้ว

## ทางเลือกที่พิจารณาแล้วไม่เอา

| ทางเลือก | เหตุผลที่ไม่เอา |
|---|---|
| ล็อกเพดานแคบต่อ `kind` (เช่นยา ≤ 120 นาที) | เป็นการตัดสินทางคลินิกแทนคนที่อยู่ในบ้านนั้น · ยาวันละครั้งกับยาสี่เวลาไม่เหมือนกัน |
| ต้องให้คนที่สองอนุมัติเมื่อตั้งค่ากว้าง | หนักเกินสำหรับฟิลด์นี้ · และจะทำให้ทีมดูแลเลี่ยงไปตั้งค่าที่แคบเกินจริงแทน ซึ่งอันตรายกว่า |
| เตือนด้วย log อย่างเดียว | คนตั้งค่าไม่ได้อ่าน log · คำเตือนที่ไม่ถึงคนตั้งค่าคือคำเตือนที่ไม่มี |
| ไม่ทำอะไรเลย ปล่อยตามเดิม | ค่าที่เคยไม่มีผลวันนี้มีผล · ปล่อยไว้คือรอให้มีคนเจอด้วยตัวเองว่าคำเตือนหายไป |

## Migration impact

ไม่มี schema เปลี่ยน · แถวเดิมที่ `grace_minutes` อยู่นอกช่วง (ถ้ามี) **ไม่ถูกแก้อัตโนมัติ** —
การแก้ข้อมูลของผู้ป่วยเงียบ ๆ เป็นสิ่งที่ repo นี้ห้ามตัวเองไว้ · ด่านใหม่บังคับเฉพาะตอนเขียน

## เทส

`test_a_grace_that_expires_before_a_person_can_react_is_refused` ·
`test_a_grace_longer_than_a_day_is_refused` ·
`test_an_unusually_wide_grace_is_allowed_but_never_silent`

## ข้อที่ยังต้องทำโดยคน ไม่ใช่โดยโค้ด

**ต้องบอกทีมดูแลที่ตั้งค่าไว้แล้ว** ว่า `grace_minutes` เริ่มมีผลจริงกับสิ่งที่ผู้ป่วยเห็น ·
โค้ดกันค่าใหม่ที่ไร้ความหมายได้ แต่กันความเข้าใจผิดของคนที่ตั้งไว้ก่อนหน้านี้ไม่ได้
