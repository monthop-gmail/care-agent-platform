# ADR-0019: เพดานหนึ่งนาทีของ `resume` เป็นค่าชั่วคราว และนี่คือเครื่องมือที่จะใช้ตอบว่าถูกหรือไม่

**Status:** Accepted (2026-09-28) — **ค่าที่ตั้งไว้เป็น provisional**
**ตอบ:** `task-6bb0d2bd` Phase A ข้อ 3 · ต่อจาก [ADR-0016](0016-a-deadline-is-a-care-decision.md) ข้อที่ยังไม่ตัดสินข้อ 3

## Context

ADR-0016 ให้ `device_resume` สดได้ 1 นาที พร้อมเพดานแข็ง · เลขนี้มาจากเหตุผล
("คนยังนั่งอยู่หน้าจอในครั้งเดียวกัน") **ไม่ได้มาจากการวัด** และ ADR-0016 เขียนข้อนี้ไว้เอง

## Decision

### 1. คงค่าไว้ที่ 1 นาที และประกาศว่าเป็นค่าชั่วคราว

ทิศของความไม่แน่นอนสำคัญกว่าตัวเลข:

> ตั้งสั้นเกินไป ผลคือจอไม่กลับมาเล่นต่อ และมีคนต้องกดเอง — น่ารำคาญ แต่เห็นได้และแก้ได้
> ตั้งยาวเกินไป ผลคือจอสว่างขึ้นมาเองตอนที่คนหลับไปแล้ว — **ปลุกคน** และไม่มีใครรู้ว่าทำไม

เมื่อยังไม่มีข้อมูลจากบ้านจริง ค่าที่ควรอยู่คือค่าที่พลาดแล้วเห็น

### 2. ห้ามหลวมกว่า `pause` ไม่ว่าทางไหน — บังคับด้วยเทส

`test_resume_can_never_be_looser_than_pause_for_any_trigger` ไล่ทุก trigger ในทะเบียน ·
เพิ่ม trigger ใหม่โดยไม่ตอบข้อนี้ไม่ได้

### 3. เครื่องมือที่จะใช้ตอบ — วัดจาก transport ไม่ใช่จากคน

`RuntimeStats.headroom_buckets` เก็บว่า **ตอนลงมือจริง เหลือเวลาอีกเท่าไร** เป็นถังหยาบ
สี่ถัง (`lt_1s` · `lt_5s` · `lt_30s` · `ge_30s`) แยกตาม `expiry_class`

🔒 สิ่งที่มันตั้งใจ **ไม่** เก็บ: ไม่มีเวลาจริง ไม่มี id ผู้ป่วย ไม่มีว่าเปิดอะไรอยู่
ไม่มีว่าดูนานเท่าไร · มันตอบได้คำถามเดียวคือ "เพดานที่ตั้งไว้คับเกินไปหรือเปล่า"

อ่านผลอย่างไร:

| ที่เห็นใน pilot | แปลว่า |
|---|---|
| `device_resume` ตกถัง `lt_1s` บ่อย | คำสั่งไปถึงแบบฉิวเฉียด — 1 นาทีคับเกินไปจริง |
| `expired_by_class["device_resume"]` สูง | คำสั่งไปไม่ทันเลย — ต้องดูรอบ poll ก่อน ไม่ใช่ขยายเพดาน |
| ทั้งสองค่าต่ำ | เพดานพอ · ไม่ต้องแตะ |

**เกณฑ์ทบทวน:** ถ้า `lt_1s` เกินหนึ่งในสี่ของ `resume` ทั้งหมดในรอบ pilot ให้กลับมาทบทวน
ค่านี้ด้วยข้อมูล ไม่ใช่ด้วยความรู้สึก

### 4. สิ่งที่ยังไม่ทำและตั้งใจไม่ทำ

ไม่วัด "ผู้ป่วยกดอะไรบ้าง" ไม่วัด "จอเปิดอยู่นานเท่าไร" ไม่วัด "ใครอยู่หน้าจอ" ·
สามข้อนี้ตอบคำถามเรื่องเพดานได้แม่นกว่า และ **ทุกข้อคือการเก็บพฤติกรรม** ซึ่งชนข้อจำกัดที่
`platform-contract.yaml` ประกาศไว้เองและรอ `task-4c4a109f`

> ยอมได้ข้อมูลหยาบกว่า ดีกว่าเริ่มเก็บชนิดข้อมูลที่เรายังตอบไม่ได้ว่าเก็บได้ไหม

## ทางเลือกที่พิจารณาแล้วไม่เอา

| ทางเลือก | เหตุผลที่ไม่เอา |
|---|---|
| ขยายเป็น 5 นาทีไปเลย ให้ใช้งานลื่นขึ้น | ไม่มีข้อมูลรองรับ และพลาดไปทางที่ไม่เห็น (ปลุกคน) |
| ให้ tenant ตั้งเอง | ยังไม่มี tenant ที่สอง และข้อนี้เป็นเรื่องความปลอดภัย ไม่ใช่รสนิยม |
| วัดด้วย timestamp เต็มแล้วค่อยมาสรุปทีหลัง | timestamp ของคำสั่งที่เกิดในบ้าน + id ของงาน = ร่องรอยพฤติกรรม · ถังหยาบตอบคำถามเดียวกันได้ |
| ไม่วัดเลย รอให้มีคนบ่น | คนที่ถูกปลุกกลางดึกจะไม่บ่นในช่องที่เราเห็น |

## Migration impact

ไม่มี · `headroom_buckets` อยู่ในหน่วยความจำของ adapter เท่านั้น ไม่มีคอลัมน์ ไม่มี schema
