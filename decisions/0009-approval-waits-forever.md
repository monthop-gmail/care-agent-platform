# ADR-0009: คำขออนุมัติรอได้ตลอดกาล — และเวลาไม่เคยอนุมัติอะไรให้

**Status:** Accepted (2026-08-19)
**Depends on:** [ADR-0003](0003-conformance-layer-in-app-repo.md) · [ADR-0006](0006-ai-has-no-medical-authority.md)

## Context

ADR-0006 ทำให้ action ความเสี่ยงสูงต้องมี authority เป็น `approval_required` หรือ
`human_command_required` แต่ **ไม่มีที่เก็บคำตัดสิน** — ผลคือ:

- agent เสนอคำสั่งยาได้ แต่ถ้าผู้ดูแลไม่ได้อยู่ตรงนั้นตอนนั้น ข้อเสนอก็ค้างอยู่เงียบ ๆ
  ไม่มีคิว ไม่มีใครรู้ว่ามีอะไรรออยู่
- ไม่มีบันทึกว่า "ใครอนุมัติ ด้วยเหตุผลอะไร เมื่อไร" นอกจาก audit event ที่เกิดตอนลงมือ

`agent-platform` มี [`approval/v1`](https://github.com/monthop-gmail/agent-platform/blob/main/contracts/approval/v1/approval.schema.yaml)
อยู่แล้ว (semantics เป็นของ `devfactory-core` RFC-0002) ซึ่งตอบเรื่องนี้ตรง ๆ

แรงกดดันที่ต้องระวังคือแรงกดดันเรื่อง "ระบบต้องไม่ค้าง" — ทางแก้ที่ง่ายที่สุดของปัญหา
"คำขอค้างนาน" คือ auto-approve เมื่อครบเวลา ซึ่งในโดเมนนี้แปลว่า
**เวลาที่ผ่านไปกลายเป็นผู้มีอำนาจสั่งยาให้ผู้ป่วย**

## Decision

### 1. `ap_approval` เก็บทั้ง "คำขอ" และ "คำตัดสิน" แยกตาราง

`ap_approval_request` คือสิ่งที่รออยู่ · `ap_approval` คือคำตัดสินตาม `approval/v1`
คำขอหนึ่งใบมีคำตัดสินได้หลายใบ (เปลี่ยนใจได้) แต่คำตัดสินแต่ละใบแก้ไม่ได้

### 2. ไม่มี auto-approve — และไม่มีทางเขียนมันเพิ่มโดยไม่ตั้งใจ

ทางเดียวที่แถวใน `ap_approval` เกิดได้คือ `decide()` ซึ่งบังคับว่า `authority.type == "human"`
เวลาที่ผ่านไปทำได้อย่างเดียวคือเปลี่ยนคำขอเป็น `expired` — คือ **งานไม่เดิน**

> คำขอที่ไม่มีกำหนดหมดอายุ (ค่าเริ่มต้นของเรื่องยา) รอได้ตลอดกาล
> การรอนานคือความไม่สะดวก · การอนุมัติเองคือความเสียหายที่ย้อนไม่ได้

### 3. ผู้ยื่นตัดสินคำขอของตัวเองไม่ได้

`approval/v1` invariant "no agent has total authority" — บังคับด้วยการเทียบ
`authority.id` กับ `requested_by.id` และปฏิเสธถ้าตรงกัน

### 4. ทุกคำตัดสินมี `GOVERNANCE_DECISION` คู่เสมอ และ `reason` ว่างไม่ได้

`approval/v1` บังคับเฉพาะ APPROVE — เราออก event ให้ **ทุกคำตัดสิน** รวม REJECT
เพราะการปฏิเสธคำสั่งยาก็เป็นเหตุการณ์ที่ต้องตอบได้ย้อนหลังเท่ากัน

### 5. `ap_approval` ไม่รู้ว่า capability ไหนทำอะไร

โดเมนลงทะเบียนผลของการอนุมัติเองผ่าน `register_applier(capability, fn)`
(รูปแบบเดียวกับ sender registry ของ `care_escalation`) — ADR-0003 กฎ 1 ยังอยู่ครบ
โมดูลนี้ไม่มีคำว่า patient / medication อยู่ในโค้ดเลยแม้แต่คำเดียว

### 6. คนกดยืนยันตรง ๆ ยังทำได้ และไม่ทำให้เกิดใบอนุมัติปลอม

ถ้าผู้ดูแลอยู่ตรงนั้น เขายืนยันผ่าน API ของโดเมนได้เลย (นั่นคือ human command ตาม ADR-0006)
คำขอที่ค้างอยู่จะกลายเป็น `withdrawn` = "ไม่ต้องตัดสินแล้ว" ซึ่ง **ไม่ใช่** `approved`
path นี้ไม่แตะตาราง `ap_approval` เลย

## Consequences

- ผู้ดูแลเห็นคิว "รอคุณตัดสิน" ทั้งใน API และในสรุปประจำวัน — ของที่รอไม่หายไปเงียบ ๆ
- ประวัติยาชี้ตัวคนได้เสมอ: `confirmed_by` คือคนที่กดอนุมัติ ไม่ใช่ agent ที่พิมพ์ข้อเสนอ
- ระบบอาจมีคำขอค้างสะสมได้ — เป็นราคาที่ยอมจ่าย และสรุปประจำวันคือกลไกที่ทำให้มันไม่ถูกลืม
- `platform-contract.yaml` ย้าย `approval/v1` จาก `not_yet` ขึ้นมาเป็น contract ที่ใช้จริง
  และ `payload_check` validate ใบอนุมัติที่เกิดจากคนกดจริงใน scenario
