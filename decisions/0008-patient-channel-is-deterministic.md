# ADR-0008: ช่องทางของผู้ป่วยตอบแบบ deterministic ไม่ผ่าน LLM

**Status:** Accepted (2026-08-18)
**Depends on:** [ADR-0006](0006-ai-has-no-medical-authority.md)

## Context

`pstack` มี `line_oa` ที่ต่อกับ `ai_agent` ให้อยู่แล้ว — ตั้ง `agent_enabled: true` แล้วทุกข้อความ
ที่ทักเข้า LINE OA จะถูกส่งให้ Claude ตอบ ซึ่งเป็นค่าเริ่มต้นของ channel ที่สร้างใหม่ด้วย
สำหรับ use case ทั่วไปนี่คือของดีและใช้เวลาต่อไม่ถึงชั่วโมง

แต่ผู้ใช้ปลายทางของเราคือคนที่ **แยกไม่ออกว่าอันไหนคือข้อมูลจริง อันไหนคือคำตอบที่ AI เดามา**
และผลของการเชื่อผิดคือกินยาซ้ำ ไปโรงพยาบาลผิดวัน หรืองดอาหารทั้งที่ไม่ต้องงด

ปัญหาที่ตามมาถ้าปล่อยให้ LLM ตอบผู้ป่วยโดยตรง:

1. **คำตอบที่ฟังดูมั่นใจแต่ไม่มีหลักฐาน** — "น่าจะทานแล้วนะครับ" คือสิ่งที่ ADR-0006 ข้อ 5 ห้ามไว้
   แต่เป็นสิ่งที่ LLM ทำได้ง่ายมากเมื่อถูกถามว่า "กินยาแล้วยัง"
2. **คำตอบสองชุดที่ขัดกัน** — ถ้าเปิด agent ไว้ ผู้ป่วยจะได้ทั้งคำตอบจากระบบและจาก LLM
3. **ผู้ป่วยไม่รู้ว่ากำลังคุยกับอะไร** — คนกลุ่มนี้ถามซ้ำเป็นเรื่องปกติ และต้องได้คำตอบเดิมทุกครั้ง
   ซึ่งเป็นสิ่งที่ LLM ไม่รับประกัน

## Decision

**ช่องทางที่ผู้ป่วยใช้ตรง (LINE เป็นตัวแรก) ตอบด้วย intent router ที่กำหนดไว้ล่วงหน้าเท่านั้น**

- `care_line.inbound.interpret()` เป็นฟังก์ชันบริสุทธิ์ที่ map ข้อความ → เจตนา ทดสอบแยกได้
- ข้อความที่ไม่เข้าเกณฑ์ได้คำตอบว่า **"ยังไม่เข้าใจ"** พร้อมตัวอย่างสิ่งที่พูดได้
  — ไม่ส่งต่อให้ LLM และไม่เดา
- LINE channel ที่ผูกกับผู้ป่วยต้องตั้ง `agent_enabled: false` (`care_line` เตือนใน log ตอน install ถ้าเจอที่เปิดไว้)
- ทุกคำตอบมาจากข้อมูลจริงในระบบ ไม่มีการสร้างเนื้อหาใหม่

### สิ่งที่ยังใช้ LLM ได้ (ในอนาคต)

| ใช้ได้ | ทำไม |
|---|---|
| ช่วย **caregiver** สรุป/ค้นข้อมูล | ผู้ดูแลประเมินคำตอบเองได้ และ RBAC/consent ยังบังคับอยู่ |
| ถอดความจากใบสั่งยา/เอกสาร → **proposal** | ผลลัพธ์ต้องผ่านการยืนยันของคนอยู่แล้ว (ADR-0006) |
| จัดหมวดหมู่ journal ที่ผู้ป่วยบันทึกไว้ | เป็นการช่วยจัดของที่มีอยู่ ไม่ใช่สร้างข้อเท็จจริงใหม่ |
| ตอบผู้ป่วยเมื่อมี guardrail ที่พิสูจน์ได้ | ต้องมี ADR ใหม่ + adversarial test ก่อน |

## Consequences

- เพิ่ม intent ใหม่ = แก้โค้ด + เพิ่มเทส ไม่ใช่แก้ prompt — ช้ากว่าแต่พฤติกรรมคงที่และตรวจสอบได้
- ครอบคลุมได้จำกัดในช่วงแรก ผู้ป่วยที่พิมพ์นอกแบบจะเจอข้อความ "ยังไม่เข้าใจ" บ่อย
  → รับได้ เพราะทางเลือกอีกทางคือคำตอบที่ผิดแต่ฟังดูน่าเชื่อ
- ต้องเก็บสถิติว่าข้อความแบบไหนตกไป `unknown` บ่อย เพื่อรู้ว่าควรเพิ่ม intent อะไร
  (`care.orientation.delivered` และ audit event อื่นเก็บให้อยู่แล้ว)
- ถ้าวันหนึ่งจะเปิด LLM ให้ตอบผู้ป่วย ต้องมี ADR ใหม่ที่ supersede ข้อนี้ พร้อมกลไกที่พิสูจน์ได้ว่า
  โมเดลไม่ตอบเกินหลักฐาน ไม่ใช่แค่ prompt ที่บอกว่าห้ามเดา
